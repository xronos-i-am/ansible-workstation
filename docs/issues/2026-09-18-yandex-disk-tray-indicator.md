# Индикатор Яндекс.Диска в трее: статус демона и статус синхронизации

## Задача

Сейчас состояние Яндекс.Диска видно только из терминала — `yandex-disk status`. Нужен простейший
индикатор в трее, который показывает две вещи:

- **статус демона** — запущен или нет;
- **статус синхронизации** — идёт обмен, всё синхронизировано, пауза, ошибка.

Готовое решение не подходит: пакета `yandex-disk-indicator` под Ubuntu 26.04 нет (в apt
отсутствует; в бэкапе на самом Диске лежал только архив `yandex-disk-indicator-1.12.2.zip`).
Поэтому первым шагом — исследование, а не сразу код.

## Что исследовать

Выбор подхода — часть задачи. Проверить и зафиксировать в этом тикете выводом:

- **Способ вывода иконки.** Сессия — GNOME Shell 50.1 на Wayland; трея как такового нет,
  иконки показывает расширение `ubuntu-appindicators@ubuntu.com` (включено) по протоколу
  StatusNotifierItem. На машине есть `libayatana-appindicator3-1` и рабочий `python3-gi` с Gtk3 —
  то есть вариант «python3 + AyatanaAppIndicator3» стартует без единого нового пакета.
  Альтернатива — расширение GNOME Shell на JS: роднее панели, но переписывается под каждый
  мажорный релиз GNOME. Решить, что дешевле поддерживать.
- **Откуда брать статус.** `yandex-disk status` печатает первой строкой
  `Synchronization core status: idle` (наблюдались значения `idle`, ожидаются также `busy`,
  `index`, `paused`, `error`). Проверить, что именно возвращает команда при остановленном демоне
  и как отличить «демон не запущен» от «ошибка синхронизации» — это две разные иконки.
- **Как опрашивать.** Периодический вызов CLI (раз в несколько секунд) против слежения за
  служебными файлами в `~/.yandex-disk/.sync`. Оценить, не жрёт ли поллинг заметный CPU в покое.
- **Автозапуск.** Сейчас сам Диск стартует через `~/.config/autostart/Yandex.Disk.desktop`.
  Решить, чем запускать индикатор: своим `.desktop` в autostart или `systemd --user` юнитом.
- **Иконки.** Взять из темы (`emblem-synchronizing`, `emblem-ok`, `dialog-error` и т.п.) или
  положить свои в репозиторий.

## Критерий готовности

- [ ] В трее висит иконка, по которой различимы состояния: демон остановлен, синхронизация идёт,
      всё синхронизировано, пауза, ошибка.
- [ ] Наведение или меню показывает текстом то же, что первая строка `yandex-disk status`.
- [ ] Индикатор не падает, если демон не запущен или `yandex-disk` вовсе не установлен —
      показывает состояние «нет демона», а не исчезает.
- [ ] Автозапуск при входе в сессию, раскладка выбрана по итогам исследования.
- [ ] Всё ставится ролью плейбука: `roles/<имя>` + строка в `playbook.yml`, руками ничего не копируется.
- [ ] В тикете дописан раздел `## Итог` с тем, какой подход выбран и почему остальные отброшены.

Минимум умышленно скромный: это индикатор состояния, а не клиент. Управление демоном
(старт/стоп/пауза из меню) — за рамками, если не окажется, что оно бесплатно.

## Проверка

```bash
# индикатор виден в панели и реагирует на смену состояния
yandex-disk stop  && sleep 2   # иконка «демон остановлен»
yandex-disk start && sleep 5   # иконка «синхронизация» → «всё синхронизировано»
yandex-disk status | head -1   # то же, что показывает индикатор

# ставится плейбуком
cd ~/projects/ansible/workstation
ansible-playbook --syntax-check -e user=dev ./playbook.yml
ansible-playbook --list-tasks  -e user=dev ./playbook.yml | grep -i yandex
```
